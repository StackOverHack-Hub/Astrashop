# Astrashop backend review

Reviewed `build/astrashop-mvp...claude/backend` at `26835f5`. The following findings come from source review and AWS documentation. Deployment and a live DynamoDB run remain unverified.

## Checks without a blocking finding

- **Atomic writes.** The reserve decrement and reservation creation commit together. Collect and release both condition the reservation update on `HELD`, and release increments stock in the same transaction. Those conditions prevent both terminal transitions from committing and prevent double restock. The reported race is in the error classification.
- **CORS and SAM wiring.** The HTTP API allows `content-type` and `x-shop-key` and the methods used by the frontend. API Gateway handles browser preflight before the Lambda's shop-key check. SAM generates the inline API definition and uses the `$default` stage when none is specified, so the base URL output is consistent with the declared routes. `Update` and `Put` transaction members use their underlying IAM actions. Verify the translated template and smoke-test shop GET, PUT, and POST preflight and a rejected key from the deployed frontend origin before freezing.
- **Test gap.** The fake database checks and applies each transaction synchronously, and all its reads reflect the current map. The existing tests cover the conditional logic but do not model read lag, DynamoDB conflicts, validation, pagination, or browser preflight.
